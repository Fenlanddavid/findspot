# FindSpot v4.12 review remediation

Date opened: 2026-07-27

Baseline: v4.12.6, including RRRA engineered-roads slice 2 and its
session-coverage clock-fixture correction.

Status: BGS Worker deployed and verified; v4.12.7 app release approval pending

## Compatibility guardrails

- No Dexie schema version change.
- No backup table or backup-format change.
- Existing user-authored coverage, prediction, and calibration records remain
  intact.
- Regenerable geology cache records may be invalidated by an explicit
  classifier-version bump.
- Previously resolved prediction outcomes are not reclassified.

## DS decisions

### Find/prediction time gate

Decision: strict event-time gate.

A valid `foundAt` is authoritative. When it is absent or invalid, a valid
`createdAt` is the fallback. A find whose authoritative timestamp predates the
prediction's `surfacedAt` does not count as a hit. This prevents recording
backlogs from inflating calibration while retaining a safe fallback for legacy
finds without a usable event time.

The change applies to future resolution attempts, including predictions that
are still unresolved when the change lands. Existing resolved outcomes and
aggregates are not rewritten.

### Session-coverage edit deadline

Decision: re-derive editability when the 48-hour deadline passes while a view
is open.

Both permission-level and direct session review entry points switch to
read-only state live. Mutation-side deadline validation remains the enforcement
boundary.

### Geology modifier representation

Decision: honest scalar simplification.

The seven-slot table is replaced with one bounded modifier per geology class.
Current effective scores are retained, so user-visible ranking behaviour does
not change. The regenerable geology cache classifier version is bumped because
the cached context shape changes.

### Coverage calibration thresholds

Decision: retain the current conservative thresholds pending field evidence.

No section-size, reported-confirmation, or tracked-coverage threshold changes
are included in this remediation. Any later change requires a separate slice
that distinguishes section layout from negative-evidence confidence and
explicitly preserves existing coverage history.

## Slice sign-off

### R1 — diagnostics integrity and field performance

- BGS layer fetches now distinguish timeout, request failure, invalid response,
  genuine empty response, and parsed data. A failed layer cannot be combined
  with a successful layer into a partial classification.
- Request and response failures reach the Field Guide warning path and are
  audited as `request_fail` or `invalid_response`. Two valid empty feature
  collections retain the existing `empty_response` meaning.
- Audit-history caveat: before this release, some network and CORS failures
  were recorded as `empty_response`. Queries spanning the release boundary
  must not interpret all historic `empty_response` rows as confirmed data-free
  tiles.
- Reconciliation of unchanged coverage sections performs zero calls to
  `deriveSectionCandidates`. The fixture fast path has a 50 ms ceiling to avoid
  a brittle wall-clock ratchet; zero derivations is the primary performance
  invariant.

### R2 — behaviour consistency

- Genuine empty geology tiles use a validated marker in the existing geology
  cache store and observe the populated-entry TTL. The second fixture scan
  performs no BGS fetch.
- Permission and session coverage views use the same accessible preparation
  error component.
- Both views re-evaluate editability at the next 48-hour deadline while open;
  the mutation command remains authoritative if a race occurs.
- Prediction matching uses valid `foundAt` as authoritative and falls back to
  `createdAt` only for legacy records without a valid find time. No historic
  resolution or calibration row is rewritten.

### R3 — proxy and infrastructure hygiene

- The BGS Worker reads its origin allowlist from `ALLOWED_ORIGINS`, rejects
  absent and unlisted origins, echoes only a matched origin, and adds
  `Vary: Origin`.
- Edge-cache entries remain origin-neutral; CORS headers are applied to the
  response after the cache lookup, preventing one allowed origin from leaking
  into another origin's response.
- The automated matrix covers production browser/PWA origin, localhost,
  preflight, cache hits, missing Origin, and an unlisted origin.
- Staged-preview and post-deploy Chromium requests from the real production
  origin and localhost both read a 200 BGS GML response. Installed PWA traffic
  uses that same production origin and cross-origin request path.
- Live cache-hit probes echoed the production and localhost origins
  independently. Missing and unlisted origins returned 403, and an allowed
  preflight returned 204 with `Vary: Origin`.
- BGS attribution is updated to 2026 and app display copy is centralised in one
  shared constant.
- All CI jobs use Node 22.22.2.
- Wrangler 4.114.0 dry-run bundle: 11.12 KiB upload, 3.01 KiB gzip.

### R4 — geology modifier representation

- The decorative seven-slot representation is replaced by one scalar per
  geology class. Characterization tests pin all class outputs.
- Scalars preserve the previous effective net values, so hotspot scores,
  gating, ordering, and confidence thresholds do not change for current users.
- The geology classifier/cache version is 3 because the cached context shape
  changed. This invalidates only regenerable geology cache entries.
- The obsolete “Phase 1: all zero” comment is removed.

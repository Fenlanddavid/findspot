## Current position

The visible V5 work is implemented in the working tree and currently passes the automated release checks described below. It has not been committed during this session and the repository contains other pre-existing/user-owned changes. Do not reset or broadly revert the worktree.

V5 now has a credible visible change without replacing FindSpot's authoritative models:

- Contextual Home fills the existing “Today / Continue where you left off” slot.
- An unfinished existing Session reconstructs the active detecting workspace.
- The active workspace provides Map, Record, Session and one-tap Guide destinations.
- The Permission page, session-start screen, session review and field/coverage cards have been visually simplified.
- The permission remains reachable from the workspace menu; Classic active-session access was retired after the subsequent parity pass.
- Coverage presentation avoids percentage claims and uses derived local evidence.
- Durability and release preparation use the existing storage/version systems rather than parallel models.

The programme brief is `docs/programmes/v5-product-engineering-brief.md`. The shipped-state inventory is `docs/programmes/v5-shipped-state-inventory.md`. Later accepted architecture decisions take precedence where they explicitly supersede the brief or this handoff.

## Work completed tonight

### Active detecting workspace

- Added a field-oriented active-session shell derived from the existing Session record.
- Map, Record, Session and Guide remain the four primary destinations.
- Finish remains pinned and permission/application navigation remains reachable; there is no Classic active-session route.
- Recording state, recent activity, boundary state, start-point distance and field actions were refined for outdoor use.
- Quick find, surface observation, undug signal, saved point, start point, note and significant-find actions use the active session context.
- Session reload/reopen reconstructs the shell from durable state.
- The observations count was removed from the compact session/review presentation where it added density without enough value.
- The completed-session review has a more prominent close action.

### Active-session map and Guide

- Added Satellite, LiDAR, OS Maps and Roman Roads to the session map using the Field Guide-style layer control.
- Layer controls were moved beneath the trail control to reduce map clutter.
- The quick Find action sits above MapLibre/OSM attribution rather than being obscured by it.
- Roman Roads information/attribution was retained; credits also remain in Settings.
- Guide launched from the session carries the active session, permission, selected field/boundary and scan target.
- Guide fits the selected session boundary where available and can automatically scan the relevant permission point.
- The Guide active-session route retains an authoritative route back to the live session and a reachable Finish action.

### Permission page

- Permission options are consolidated into a menu.
- Landscape investigations, scan accuracy/performance, offline access and notes use progressive disclosure.
- The permission map and Sessions/Visits presentation were made more compact.
- The latest Fields & Coverage refinement is in `src/components/PermissionFieldsColumn.tsx`:
  - one neutral Fields & Coverage surface instead of the green-washed stacked treatment;
  - summary metadata for field count, acreage and visits;
  - map is the visual anchor, with a smaller Expand control;
  - each field rests as a compact summary and only one field expands at once;
  - Start visit and Guide remain immediately available;
  - Locate, notes, edit boundary/field and delete live in the field overflow menu;
  - normal mapped boundaries are silent, while a missing boundary is highlighted;
  - Ground coverage and Show gaps are combined under Coverage and details;
  - the nested field-list scrollbar was removed in favour of normal page scrolling.

### New-session start flow

- The old multi-panel “New Session” form was replaced by `src/components/session/NewSessionStartCard.tsx`.
- Starting a visit now requires only the existing permission context and a clear Start detecting action.
- Date/time is not editable before starting. The durable session date/start time is the instant Start detecting is pressed, not the time the page was opened.
- GPS is not requested before starting. Session location remains unset until a trail or recording action needs location.
- A field supplied in the route is inherited; a sole field is automatically selected; permissions with multiple fields get a compact area selector.
- Ground condition and a visit note remain available behind one optional disclosure.
- The complete editor for an existing session still permits correction of date, field, GPS, ground and notes.

### Coverage language and integrity

- Permission cards no longer display “% left” or another coverage percentage.
- Gaps are described qualitatively and only as recorded coverage evidence.
- Shared permission-coverage wording is in `src/shared/coveragePresentation.ts`.
- Marked searched areas remain visibly acknowledged when contributing to the gaps view.
- Historical review must continue to use `sessionCoverage` for the historical session and must not substitute current permission coverage.

### Home, continuity, durability and release support

- Contextual Home services, active-session context, session review and continuity services are headless/React-free at their service boundaries.
- Continuity derives from authoritative source records and does not create task copies.
- Startup guards cover global session loads, Field Guide scans and continuity on the startup-critical path.
- Backup/restore validation includes V5 durable records; derived presentation state is recomputed.
- `scripts/prepareRelease.mjs` and release architecture tests cover consistent version preparation.

## Decisions that should not be accidentally reversed

1. Do not add a second contextual block above Home's existing Today slot.
2. Do not create a second ActiveSession or recommendation domain model.
3. Keep Guide one tap away inside the active shell.
4. Do not require GPS, editable date/time or tracking setup before a visit can start.
5. Keep field selection only where it materially establishes boundary/Guide context.
6. Keep field management secondary to Start visit and Guide.
7. Keep coverage and gap controls together under one field disclosure.
8. Do not reintroduce coverage percentages or language claiming the user has not searched somewhere.
9. Preserve existing application routes. Workspace rollback is code rollback to the prior release, not a runtime Classic escape.
10. Do not weaken backup, startup, architecture or release checks to land visual work.
